## Admission and selection

Main and engineering have identical checked-in workflow files. Ordinary pull requests, including drafts, and pushes to main run Documentation CI. The board-drc matrix invokes pinned native DRC with schematic parity and zone refill on K/JL/JR, with a 45-minute ceiling per runner. The matrix may execute three runners at once. The most recent main run on the compared SHA passed those three jobs in 260, 83 and 88 seconds respectively. That run used main's different boards. Six other workflows have manual dispatch triggers. Inspection found no deployment action in these workflows. External hosting integrations require separate observation.

DS-133/134 and the WSL native-composition receipt retain the specific DRC/fill hold. The isolated aggregate and its historical no-fill receipt do not cover those three jobs. The owner authorizes eligible source merges. Before opening a PR, bind the exact proposed head, base, paths and native board hashes, observed Actions capacity, finite matrix budget, review authority and cleanup/cancellation conditions to an affirmative CI-operation admission covering the PR and post-merge triggers. The historical CI gate is independent of the hardware-adoption, manufacturing and routing holds. Branch protection API returned HTTP 404 “Branch not protected” and the effective branch-rules endpoint returned an empty list. Project-required verification and independent review still apply.

**No substantive main-target PR was eligible at this checkpoint.** The repairs depend on the engineering scene; the rejected candidate cannot become main's default through a checker PR. A smaller reviewable candidate would replay the rejected scene under an explicitly frozen study against reachable pinned sources, keep the existing main default, and port only a fail-closed consumer that actually exists on main. Its importer, snapshots and tests require implementation and independent clean-checkout reproduction. That alternative integrates diagnostic capability only. The substantive path requires a compliant S10, independent review of its inherited dependency closure including the board changes, and explicit native CI admission. Neither a summary document nor the historic independent work substitutes for that scope. S11 remains downstream of accepted S10.
