The default-tolerance operating point is not the linear one either. Transient op left the output at
v(out) = 11.97 V, at the +12 V rail, with IN- at 2.34 V against IN+ at 5 V. The intended output is 9 V: gain 1.8 on
the 5 V reference, through R1 = 50 kΩ and R3 = 40 kΩ. The deck had its corner at TMUX output capacitance 0 and the
Ruling 6 bracket to AGND. In every step, gmin stepping and source stepping fail before transient op takes over. A
1 nF capacitor does not change the DC solution, so the zero-stray H-REF9 decks probably depend on transient op too.
That is not shown, because no zero-stray deck ran. These are file contents, not a diagnosis.

The other half of P7 passes. `/W1/DRIVE_INV_SUM` at 1 nF gives a phase margin of 3.004° (fails K1) and 290.7 %
overshoot (fails K4).

## One tooling fix and one interpretation were needed during the run

- **Tooling fix.** The first `--controls` call crashed in the study's own `loop_run()`, 5 s in, after one P5 deck.
  The M3 swapped-probe deck has no falling unity crossing, and the code indexed an empty list.
  `loop_run()` now returns no margin in that case, which counts as a failure for P5 and P8 and as the expected
  outcome for M3. The whole `--controls` was then rerun from the start. No criterion changed.
- **Interpretation (stricter reading).** M10 says a `paper_screen` object "changed or removed" must not fail P4b,
  while M11 says a row "losing it" must fail. The test reads "removed" as the object's content removed (for example
  `{}`) and treats loss of the key as M11. So P4b's exclusion set must stay exactly the 16 rows.
