# K full solve: restart-safe column checkpoints (read-only design audit)

## Finding

`current_trial_matrix.current_matrix` and `potential_trial_matrix.potential_matrix` already compute the 2,287 finite profiles in fixed, eight-column batches. Each batch finishes a rectangular `energy[:, start:stop]` block plus per-profile residual-work inputs and numerical gate receipts. The expensive per-column solve can be resumed after reconstructing the same mesh, full operator, factorization, source projection, and initial current source-lift Gram. The current `solve_conductor_volume.py` only caches meshes; losing its process loses all completed profile columns. A completed batch is **not** a result certificate by itself: the full unsymmetrized Gram must still pass reciprocity, the assembled current/potential matrices must pass the final bracket eigenvalue gate, and the existing source/prerequisite rechecks and exclusive result publication must still occur.

## Recommended implementation

1. Add one optional checkpoint sink to each matrix function, called **after** all existing per-batch work and the `local_residual <= 1e-8` gate. Do not alter source projection, LU/refinement, current reconstruction, correction, residual-work calculation, profile order, batch size, or summation order. On resume, place a verified column block directly into the same preallocated `energy` matrix and restore exactly the arrays and receipt rows that the existing loop would have appended. Keep the current starting `S.T @ diag(reciprocals) @ S + lift` and potential zero matrix recomputed afresh; checkpoint the **post-addition** columns so the original `+= basis.T @ field` is not repeated.
2. Bind one immutable run key to SHA-256 of frozen native export; the complete `model_source_sha256` map (including the new checkpoint code); all prerequisite receipt bytes/hashes; exact `profile_bytes` and ordered `(layer, patch.wkb, signed current)` profiles; all mesh parameters, `rho`, thickness, mode, batch size, and NumPy/SciPy/Shapely/Python versions. Also hash the **constructed operands** before admitting any checkpoint: canonical CSR/CSC shape, dtype, `indptr`, `indices`, `data` for solve matrix, energy matrix where distinct, `basis`, and `S`; hash the initial current source-lift Gram or its components. This detects changed mesh or operator construction even when the source inputs appear equal. Existing mesh cache keys alone are insufficient to bind completed numerical columns.
3. Save one file per exact `[start, stop)` range, containing the entire `energy[:, start:stop]` float64 block, per-profile `field_max`, residual-work one-norm, current correction energy where applicable, and the existing refinement, residual-work, physical KCL, and conservation receipts. Use a non-pickle format (`np.savez` with `allow_pickle=False` on read, plus strict JSON for receipts). Commit with a temporary file, flush/fsync, atomic rename, and a small manifest containing run key, range, schema version, payload byte count, and SHA-256. A batch whose file/manifest pair is incomplete, corrupt, nonfinite, wrong shape/dtype/range, or has a mismatched key is rejected and recomputed; it must never be counted as passed. Reject duplicate or overlapping ranges. Do not write a checkpoint before the batch's numerical gate passes.
4. At resume, verify every checkpoint against the **newly assembled** operands and profile receipt, then restore only a contiguous prefix of full eight-column batches (the last batch may be shorter). Refuse gaps or overlaps; recompute the first incomplete batch. Restore each per-batch receipt at its original index and verify `start`/`stop`. Recompute the scalar maximum residual from the restored physical-gate components (current) or full equation residual receipts (potential), checking every restored component against `1e-8`. Recompute `residual_work_diagonal`, `conserving_upper`, reciprocity, gap eigenvalue, and publication gates using the complete matrix, exactly once, after all columns are present. No precomputed accepted final Gram should be loaded.
5. Recheck the run-key source hashes and native/prerequisite bytes before **each** checkpoint commit and at final publication. Keep checkpoint files under the ignored `.circuit-cache` output stem, never publish them as result receipts. Preserve the existing fresh-stem rule for the final JSON/profile pair; a restart may reuse the same stem only while both final files are absent. A completed or partial public receipt still requires a fresh stem or explicit investigation.

## Practical guard interaction

Use `bash $HOME/.codex/scripts/heavy-guard.sh --max-run <bounded-seconds> --min-mem-mb <normal-gate> --label ... -- <solver-command>` in the foreground. The guard holds the machine-wide slot for each attempt and kills the command tree on timeout or daemon death; a checkpoint committed before that interruption survives. Exit 75 means the solver never ran. `ENV_SUSPECT` is not a numerical pass and receives the policy's one rerun; an actual residual, conservation, reciprocity, or bracket failure is `FAIL` and must be fixed. Choose a max run that includes the expected batch work or use the policy's bounded attempt; never bypass or weaken the guard merely to complete K.

## Risks and validation before relying on it

- The key must include the checkpoint implementation itself. Adding it to the source hash list invalidates historical receipts by design; do not rebind them.
- Hashing only source filenames and the native board is inadequate because mesh cache corruption or changed numerical libraries could otherwise reuse incompatible columns.
- A resumed run must match an uninterrupted run within the existing numerical enclosure; exact float equality is a useful test on a small fixture, but the real contract is preserved gates and no narrower bounds. Test interruption after one batch, deliberate mutation of payload/manifest/operator/profile/source hash, duplicate/gapped batches, current KCL failure, potential residual failure, and final reciprocity/bracket failure.
- Atomic files with a checksum protect interrupted writes and accidental corruption, not a malicious actor able to rewrite both payload and manifest. These checkpoints are local diagnostics only; final source and native gates remain mandatory.

No solver edits or heavy runs were made for this audit.
