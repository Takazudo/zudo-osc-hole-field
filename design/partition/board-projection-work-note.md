# Issue 36 board projection work note

The selected nine-board assignment is projected from the current master source by `scripts/schgen/project_boards.py`. Each original package keeps its master reference, value, footprint, DNP state, pin map and source hierarchy identity. The exported board root paths in `schematic/boards/` point to the generated project sheet sources under `boards/`. No panel UID or module is reassigned by this generator.

Local sheet nets receive deterministic global tokens in the board schematics so their names remain unique after a master module is sliced onto multiple boards. `design/reports/board-net-tokens.json` reverses each token to the native master name. The verifier compares every exported physical pin to the native master netlist, then requires the declared harness and factory-wire graph to connect each multi-board net. It rejects undeclared crossing, swapped mate pins, duplicate/missing packages, split islands and Sensitive connector nets. The audit-only CN301/XB301 parts and pins are excluded from the physical board set. No load-side continuity is inferred through either abstract boundary.

The 390 JST headers retain manufacturer pins 1–3/7/8 and two unnetted mechanical pads. Exactly 1,822 external crimps and 390 housings are assembly items, with no PCB footprint of their own. Twenty-four custom copper lands represent the twelve factory load-side wires. `design/reports/board-side-map.json` carries every physical reference's selected side and explicit native KiCad rotation/footprint origin. The connector report records per-pin planning currents against the 0.5 A contact derating. These values and current sharing are conditional; hot resistance, partial mating, support, strain and service qualification remain NOT RUN.

All generated schematics and future PCBs are unvalidated drafts. Exact source/inlet/protection/bulk realization remains open under #57/#59; installed adapter/optical/mechanical behavior remains NOT RUN under #55/#64/#65. No fabrication order files are generated.

The pinned KiCad 10.0.6 ERC run reports zero errors across all nine board projects. It still reports warnings: 268 J, 137 P, 212 K, 32 EL and two for each octave adapter. These are primarily pin-to-pin type and off-grid endpoint warnings in the draft generated drawings; zero ERC errors is not electrical validation. KiCad's package-level netlist may select a different unit's `Role`/`Island` field for a multi-unit IC after board slicing. The per-unit schematic source fields are retained; native parity explicitly gates package value, footprint, MPN, manufacturer, LCSC and panel UID, plus every exported pin net.
