## Recommended implementation boundary

1. Keep external production scheduling batch16 and unchanged unit/batch identities. Slice each Wb batch into at most8-column views.
2. Refactor common numerical body into a private bounded helper. The public `refined_solve(...,extended_solution=True)` must still refuse multicolumn RHS, as existing tests require. Only the dedicated projection helper accesses the private at-most8-column extended path. Validate shape/width before `lu.solve` or allocation; reject wider arrays. Do not add an unbounded boolean allowing arbitrary extended matrices.
3. Preserve one factorization, original coefficients/permutation, same initial solve plus exactly3 corrections, same best-iterate selection and bounded sparse residual scratch. Selection of best iterate is per subblock; numerical criteria remain unchanged.
4. Project e=`sum(rhs*U,axis=0)` and q=`Bf.T@U` while U is extended. Store only small float64 e/q arrays. Never round U before either projection. Empty projection blocks should return correctly shaped empty e/q and residual0 without invoking a max-on-empty refinement helper.
5. Explicitly reject nonfinite or negative residual diagnostics. Preserve original16-column normalization: combine each subblock relative residual times its own RHS maximum, take maximum absolute residual, divide by original Wb maximum (with same1e-300 floor). Do not silently normalize over the entire96-pad unit or replace this with maximum per-column ratio.
6. Delete U after each subblock's projection, before starting the next refinement. Python evaluates a new RHS before rebinding a previous U variable; leaving oldU live during the next helper would add an avoidable full extended block to peak memory. Prefer a projection helper returning only e/q/residual so callers cannot retain all U blocks.

## Memory and runtime claims

On this WSL platform longdouble itemsize16: old16-column float64 x/best each128bytes per node; candidate8-column longdouble x/best each128bytes per node. Residual and LU correction arrays shrink from128 to64bytes per node each. Initial float64 solve for8 RHS is half the original size; common Wb remains16-wide float64. Sparse residual processing still uses one extended node scratch plus65,536-entry products and does not copy the full sparse matrix extended. Final projected e/q remain float64.

This is an array-budget comparison, **not measured production RSS**. RHS contiguity conversion, sparse LU workspaces, mixed-type `Bf.T@U` conversion, x+correction temporaries and allocator retention still contribute. Dot product may temporarily widen Bf's at-most-small terminal basis; account for it. Project e and q sequentially; avoid retaining their full-node temporary products. Do not allocate both extended U blocks simultaneously.

Two eight-RHS solves preserve more batched triangular-solve throughput than16 sequential single-RHS solves. Existing residual helper already iterates columns. Nevertheless longdouble projection and twice as many triangular-solve calls can alter runtime; **no180-second production guarantee** follows. The existing180s/2GiB/no-swap/per-unit guard is unchanged and is the actual acceptance boundary. Do not enlarge limits or silently subdivide unit identities/scheduler to hide a timeout.

Focused source regression should cover:16 columns with zero/scaled supports; blocks8+8 and a short tail; public extended multicolumn refusal; private width>8 refusal before LU; e/q float64 and analytic values; exact3correction steps per subblock; unchanged whole16 normalization; nonfinite/negative residual refusal; zero/empty projections; no full extended16 allocation. Ordinary float64 multi-RHS helper behavior should remain unchanged.
