## Quantified storage floors, not peak predictions

KA has1,515,457 nodes and1,736,692 unique pre-collapse vertices; KB has1,541,278 nodes and1,730,062 vertices. These counts come from independently bound retained receipts, not opened pickles.

| Single array | KA bytes | KB bytes |
| --- | ---: | ---: |
| One full long-double node vector (16 bytes/node) | 24,247,312 | 24,660,448 |
| Structured coordinate key table (24 bytes/vertex) | 41,680,608 | 41,521,488 |
| Vertex-to-node int64 mapping (8 bytes/vertex) | 13,893,536 | 13,840,496 |

A retained Y column has one long-double value per **free** node; its size is at most the full-vector row above. Two simultaneous full field vectors alone use48,907,760 bytes, leaving little room in a64MiB output quota if both are persisted. This is a reason to stream and dispose, not to silently omit accounting. The Python-object and decompression overhead is additional and currently unbounded by retained compressed sizes. Matrix pattern accumulation needs16×nnz bytes plus the CSR copy and comparison temporary; exact nnz storage and its live overlap must be pinned before admission, not guessed from compressed artifact size.

Historical separate-unit receipts: KA Assembly33.83s/1,025,916KiB, KB Assembly45.04s/1,034,700KiB, KA reduction27.44s/1,625,624KiB, KB reduction30.65s/1,673,712KiB, KB96-observation driving point68.52s/1,322,132KiB. These did **not** run the new combined operation or independently certify uniqueness. Their sum is not a measured combined duration; no scaling from tiny fixture timings is asserted.
