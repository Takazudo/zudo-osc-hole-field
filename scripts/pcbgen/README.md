# PCB draft sync

Run `bash scripts/kicad/run.sh python3 scripts/pcbgen/sync.py <board-id>` after the matching KiCad schematic netlist has been exported. Board definitions live in `design/boards/<board-id>.json`; the checked-in `fixture-jacks` definition demonstrates the format. The generator reads panel hardware coordinates only from `design/grid/placements.lock.json`, then translates them with `scripts/geometry/panel_frame.py:to_kicad()`.

The definition contains a panel-frame outline polygon, optional convex corner radius, 2/4/6/8 copper-layer count, preliminary layer stackup and thickness, NPTH mounting holes, copper keepout polygons, board domains, and the exact selected lockfile UIDs. Those domains and UIDs are eligibility and coordinate inputs; the exported netlist controls which footprints are populated. A netlisted `FootprintOriginMm` seeds the exact panel-frame centre, and `KiCadOrientationDeg` sets the native angle after a `BoardSide` flip. Parts without a source origin begin on a bounded off-board staging grid. Fixed panel hardware must stay on `F.Cu`. `F.Cu` faces the panel and `B.Cu` faces away. The shared panel origin is translated to `(100, 50)` mm and used for both drill/place and grid origin. Board sheet size is A2.

A footprint belongs to this generator only when its UUID equals the UUIDv5 derived from the board ID and reference. The same rule applies to outline segments, declared mounting holes, and rule-area keepouts. Sync can remove those items when the source removes them. It never removes an unowned footprint, track, via, zone, text or graphic; a conflicting unowned reference fails before the generator takes it over. Existing free footprints retain their current location. Fixed hardware footprints return to their lockfile position and are locked. Library footprints are loaded once per type, then cloned. KiCad's random generated UUIDs are rewritten after save; the postpass also sorts only owned footprint/keepout blocks so repeated syncs are byte-identical. Schematic paths use the netlist sheet and symbol UUIDs.

Fixed hardware always returns to F.Cu before the exact lockfile angle is applied.
An explicit B.Cu or conflicting `KiCadOrientationDeg` fails without saving the
board; equivalent full turns are accepted but the lockfile angle is retained.
For free components, changing the library footprint preserves position, side,
native angle and locked state. Explicit `BoardSide` then applies KiCad's native
flip, followed by an explicit `KiCadOrientationDeg` if supplied. Source-origin
locking still applies when `FootprintOriginMm` is present without `BoardRegion`;
sync never unlocks an existing free footprint. Nonfinite source angles fail.
New hidden source fields explicitly use KiCad's 0.15 mm default text thickness
so their first saved form survives reload unchanged; existing field strokes remain untouched.

`bash scripts/pcbgen/check.sh <board-id>` runs the pinned KiCad 10.0.6 DRC with schematic parity, zone refill and all severities, then writes JSON, top/bottom PNG renders and an SVG to `boards/<board-id>/reports/`. The summary separates rule violations, unconnected items and parity issues, and exits nonzero for DRC errors or parity issues. It does **not** claim that a clean rule check qualifies the PCB or its mechanical fit.

Run `python3 -m unittest scripts.pcbgen.test_pure -v` for board-definition and UUID tests and `bash scripts/pcbgen/test_fixture.sh` for the ten-jack oracle fixture. The fixture tests exact lockfile placement, zero schematic parity issues, byte-identical repeat sync, owner track/via/zone/text/graphic preservation, component re-netting, and component removal. Its jacks are deliberately unrouted; unconnected items are expected. The synthetic circuit and board are unvalidated drafts and are never fabrication order files.

The fixture also runs `fixtures/check_sync_pose.py` through the pinned oracle:
saved B.Cu hardware is repaired to its fixed front pose, conflicting fields leave
board bytes unchanged, replacement preserves both lock states and B.Cu placement,
explicit source overrides take precedence, and repeat sync stays byte-identical.
`python3 -m unittest scripts.pcbgen.test_pose -v` checks the pure source policy.

Current limitations: the stackup JSON records intent while KiCad receives thickness and copper count; detailed dielectric/material rule values await the board-stack decision. Fillets require a strictly convex polygon. The fixture cannot establish physical jack-panel fit or electrical function.

## Reviewed routing translations

`design/partition/routing-placement-translations.json` is an explicit source input to the floorplan generator. Its default empty list changes no placement. A reviewed translation binds the complete expected source row, a nonempty evidence reference and a nonzero 0.1mm-grid delta within ±2mm. It is restricted to movable JL/JR resistors outside bypass clusters; side and orientation cannot change. The generator rejects stale source rows, duplicate entries, source-edge clearance below0.30mm and courtyard separation below0.35mm. It does not repack other components.

This source geometry mechanism does not accept routed copper. Any activation still needs native10.0.6 placement, DRC/parity, warnings, original pad-group membership, settled/fresh agreement and full retained-copper checks after schematic/source regeneration. Fixed panel hardware remains bound to the original lockfile. Never edit the generated floorplan JSON to adopt a movement.

## Region placement for repeated clusters

After sync, `place.py` positions generator-owned, unlocked free footprints within the optional `regions` in a board definition. Each region names a schematic `Block` instance and a repeated `family`, plus a panel-frame `rect` `[left, top, right, bottom]` in millimetres, `side` (`F.Cu` or `B.Cu`), `edge_clearance_mm`, and `mounting_clearance_mm`. See `fixture-place-six.json` for six 17 mm translated regions. One block may declare both faces when each part has an explicit `BoardSide`. A part with `FootprintOriginMm` is checked at that exact source coordinate against its native courtyard and obstacles; it is never searched onto a different position. The placement UIDs and fixed hardware coordinates still come solely from the grid lockfile. Locked or unowned free footprints keep their locations; an absent or moved fixed footprint is an error.

Export the schematic netlist, run sync, then run `bash scripts/kicad/run.sh python3 scripts/pcbgen/place.py <board-id>`. `--board`, `--netlist`, and `--report` select alternate paths. The report defaults to `reports/placement.json` beside the board. Each schematic `Block` must have a matching region. A family is placed once from its courtyard boxes, and each repeated instance receives the same relative positions translated to its region. A component with an `Island` field naming a selected panel UID is anchored near that hardware. `DecouplingOf` can name an IC `Role` or reference; otherwise shared signal nets assign nearby passives to an IC cluster. Courtyards, both-side through-hole pads, mounting holes, keepouts, and outline edges constrain legal positions. There is no spill outside the named region. An impossible placement exits nonzero and writes an `OVERFLOW` report with the instance, needed area, and available area; it does not save the board.

Courtyard containment checks every outline edge against the complete courtyard rectangle, including concave cutouts and the closest distance to an edge or notch tip. Boundary contact is rejected; positive edge clearances retain the existing 1e-6 mm comparison tolerance. Every chosen region must agree with the native footprint face and any explicit `BoardSide`. Explicit `FootprintOriginMm` anchors retain precedence over a searched template and are never relocated; an anchored base supplies the template for later repetitions without an explicit anchor.

Run `bash scripts/pcbgen/test_placer.sh` for one-instance, six-instance, island, and overflow oracle fixtures. It checks second-run byte identity, exact 17 mm translations, zero courtyard violations, and zero schematic parity issues in KiCad 10. The fixture is unrouted, so unconnected DRC items are expected. The placer uses conservative axis-aligned courtyard boxes and a 0.5 mm search grid. The suite also rejects repeated templates on the wrong native face without changing board bytes and checks anchored-base template reuse. Its report remains `PLACED DRAFT`; final layout and mechanical/electrical qualification require later checks.

## Draft routing pipeline

Add `routing` to a board definition with `min_track_width_mm`, `net_classes`, and `zones`. Each class names exact nets and gives `track_width_mm`, `clearance_mm`, `via_diameter_mm`, and `via_drill_mm`. The `Default` class covers all other nets. A zone specifies its net, copper layers, local clearance, minimum fill thickness, and `pad_connection` (`thermal` or `full`). Its optional `polygon` selects an explicit split-plane shape; absent it, the board outline is used. KiCad applies copper-edge clearance during fill. Two-layer fixtures use ground pours; the four-layer fixture uses `In1.Cu` ground and `In2.Cu` +12 V planes. The dense fixture additionally uses an `F.Cu` ground pour to join inner-plane regions cut by connector escapes. These dimensions are draft routing inputs, not fabrication limits.

Run `bash scripts/pcbgen/route.sh <board-id>` after netlist export, sync, and placement. `--board` selects a fixture or other repository-local board path; `--threads`, `--heap-mb`, and `--timeout-sec` override the defaults in `router.env`. The default router has at most half the host's CPU threads (capped at six), a 2 GiB JVM heap, a bounded container memory limit, and a 180-second wall limit. It disables Freerouting's optional optimization stage so a bounded autoroute can write its SES result. `--no-fanout` is available for continuation runs whose existing copper already escapes SMD pins. `route.sh` enters the machine-wide heavy-run queue. Freerouting runs offline in a digest-pinned container. The pipeline updates project net classes and minimum track width, creates owned zones without deleting owner zones, fixes existing tracks/vias, fills zones, exports Specctra DSN, routes headlessly (`-de`, `-do`, `-mt`), imports SES, checks every pre-existing track/via and zone, refills, and runs KiCad 10 DRC with schematic parity. Freerouting's 2.4.1 [CLI options](https://github.com/freerouting/freerouting/blob/v2.4.1/docs/command_line_arguments.md) and [release](https://github.com/freerouting/freerouting/releases/tag/v2.4.1) are the primary command source.

The default report is `reports/routing.json` beside the board, with routed/unrouted net counts and names, via count, total track length, run time, sampled container memory peak, and separate KiCad error/warning/unconnected/parity counts. `reports/ratsnest.json` also records the complete native KiCad unconnected-edge count; large-board DRC JSON can truncate its item and net-name list, so names from that JSON are only a sample when the counts differ. `ROUTED DRAFT` requires zero KiCad rule errors, unconnected items, and parity issues. Exit 3 means `TIMEOUT DRAFT`; the report names nets from the router's final log when available and otherwise labels the pre-route DRC snapshot. Other incomplete or failed routes exit 2. A fully routed board skips the router and leaves board bytes unchanged; rule and parity errors still fail. Prepared source copper and refilled planes are also checked before invoking the heuristic router. Silkscreen warnings can remain on synthetic fixtures and are reported separately.

`--max-passes` raises Freerouting's pass limit (default 20) for a single bounded run. Before importing a session, the pipeline drops its `(placement ...)` block: routing never moves footprints, and Freerouting writes board-only NPTH footprints without an image name, which KiCad's SES parser rejects.

`finish_routes.py` is an optional finishing pass for the few connections a heuristic run leaves open. Run it through `scripts/kicad/run.sh` after `route.sh`. It finds nets that still have more than one native connectivity cluster and adds tracks and vias with a two-layer 0.1 mm grid maze search. The search keeps each net-class width and clearance, the board hole and edge clearances, and track/via keepouts, and it never places a via over an SMD pad. When no path exists, it may rip up the tracks and vias of the fewest blocking signal nets, then route them again in a new process (bounded by `--max-rips`). Rail and ground copper is never ripped up. Pads, footprints, holes, zones and keepouts never move. It writes `reports/finish-routes.json`. Re-run `route.sh` or `check.sh` afterwards; only native KiCad DRC with schematic parity decides whether the result is acceptable.

`replicate.py` copies **local-net** tracks and vias from one `Block` to translated instances of the same region family. It matches source and target parts through their `Role`/footprint signatures, pin numbers, nets, and exact footprint/pad translations. Shared rail/ground tracks and already routed target nets are left alone. The remaining shared nets should then be routed by `route.sh`. Run it through `scripts/kicad/run.sh` with `--source` and optional `--targets`; it writes `reports/replication.json`. It refuses a placement that differs from the template.

`bash scripts/pcbgen/test_route.sh --quick` builds and checks the two-layer, four-layer, six-instance replication, rerun, and timed-out barrier fixtures. `--dense` reproducibly builds the full 3 × 10 jack stress slice from retained copper sources, adds the explicit ground stitching, checks the complete DRC gate, repeats generation, and exercises missing-via and stale-geometry regressions. `--dense-route` performs a new bounded source-column/full-slice heuristic experiment and archives prior cache attempts. The accepted repair, measured failures, and ownership boundary are documented in [dense-evidence/README.md](fixtures/dense-evidence/README.md). The fixture uses audited jack footprints, one OPA4196 quad-amp **section** per synthetic indicator (one package per cell for independent routing stress), an LED and passives, and one 40-pin KiCad stock connector. It is deliberately a routing stress topology, not the proposed indicator circuit or a package-count decision. The pinned KiCad stock connector symbol fragment is retained in `fixtures/Conn_02x20_Odd_Even.kicad_sympart` (SHA-256 `247f848336a03a540f21f6ca8cd6fd064ef3f38b89cdef1e6d7a947aa7ae2d57`). `fixtures/dense-slice-report.json` records measured completion and resource results. Every autorouted PCB remains an unvalidated draft for human routing, thermal, mechanical, and fabrication review.

## Draft ground extraction numerical setup

`bash scripts/pcbgen/test_native_prerequisites.sh` runs the standalone control/core
terminal-access, enabled-foil export and core package-field regressions through
the pinned KiCad oracle under the heavy guard. These executable native fixtures
use `*_native_regression.py` names; they are not ordinary Python unittest modules.
Each run retains fresh local fixture receipts and leaves earlier evidence intact.

Use a disposable local environment; the pinned KiCad oracle exports native
geometry separately. Numerical extraction never changes a PCB or qualifies
materials, soldering, temperature, or hardware.

```sh
python3 -m venv .circuit-cache/ground-solver-venv
.circuit-cache/ground-solver-venv/bin/python -m pip install -r scripts/pcbgen/numerical-requirements.txt
.circuit-cache/ground-solver-venv/bin/python -m unittest scripts.pcbgen.test_ground_access scripts.pcbgen.test_ground_annular
```

The pins are also installed before Python unit-test discovery in CI. The separate
`power_locality_native_regression.py` runs explicitly through the pinned oracle in
CI; it proves that a pad and orphan zone cannot pass a main-network audit. Full-board
resistance solves run through `bash $HOME/.codex/scripts/heavy-guard.sh --` and
retain the board/source hashes, finite interface definitions, material conditions,
convergence limits, and exact failure reason. Native electrical connectivity,
numerical screens, and physical qualification are distinct gates.

## Grid router and cut-line capacity

`grid_dump.py` (KiCad oracle, read-only) exports pads, tracks, vias, keepouts, the outline and the native open pad islands of a four-layer board. On the host, `grid_router.py` joins each open island to its net's largest island with a grid A* path over F.Cu/In1.Cu/In2.Cu/B.Cu and through vias. `--rip` removes and reroutes named signal nets around boxed-in pins. It writes an unchecked proposal of explicit segments and vias with stable UUIDs. `grid_apply.py` (KiCad oracle) writes that proposal into a candidate board copy. Accept a proposal only after native DRC/parity, refill, ratsnest and ground checks on the candidate. Put the candidate two directories below the repository root, for example `.circuit-cache/<name>/` with the board's `fp-lib-table`, `sym-lib-table`, project, schematic and `sheets/`. Elsewhere `${KIPRJMOD}/../../` does not resolve and DRC reports spurious `lib_footprint_issues`. The raster is conservative by one cell half-diagonal; zone pours are not obstacles because they refill around new copper, so cut pours need their own ground check.

`cut_capacity.py` reads the same dump and scans vertical and horizontal lines. Demand is the number of signal nets with pads on both sides; capacity per layer is the ideal number of track centrelines at the chosen width plus clearance in the line's free runs. A signal-layer ratio below 1 proves those layers cannot carry the crossing nets; ratios near 1 are still unroutable in practice. Both tools need `numerical-requirements.txt`. `python3 -m unittest scripts.pcbgen.test_grid_router` covers synthetic routing, via use, clearance, boxed pins and capacity.

## Neck-down areas at IC pin rows

`design/partition/neckdown-areas.json` holds the neck-down rule (0.15 mm Default-class track width and signal-to-signal clearance; rails and AGND keep their net-class clearance) and, per board, the ICs that get a rule area. Inside the KiCad image, `neckdown_areas.py <board> --select` records every IC (reference `U*`) with a pad on an open Default-class net; the board's `.kicad_pro` must sit next to the board so net classes resolve. `neckdown_areas.py <board>` then draws one rule area named `pcbgen:<board>:neckdown` (nothing disallowed) over each listed IC's pads plus 2 mm on the signal layers, and writes `<board>.kicad_dru` with the matching custom rules. `route_jack_grid.py` passes the rule to `grid_router.route` and `negotiate` for listed boards: raster cells inside the areas use the neck clearance to other signal copper and full clearance to the grown rail/ground nets, path points carry a neck flag, and `copper_rows` draws segments touching an area at the neck width. Stage workspaces copy the `.kicad_dru`. Each stage's native check refills zones until the per-net island counts settle, because a single refill of fresh copper can under-count open pour islands.

## Grid routing on CI

`.github/workflows/route.yml` runs `route_jack_grid.py` on a GitHub-hosted runner (4 vCPU, 16 GB, 6 h job limit) instead of the local machine. Dispatch it from the default branch with `board`, an existing `branch`, `from_stage`, optional `to_stage`, `workers` (default 3) and `max_minutes` (default 330, at most 335). The job uses CPython 3.10 with `numerical-requirements.txt`, compiles `grid_astar.c` with the runner's `cc`, and runs KiCad through `scripts/kicad/run.sh` with the pinned image. `--max-minutes` stops the driver between stages and caps negotiation deadlines, so resumable negotiate and region state (`.circuit-cache/<board>-*.pkl`) is saved to the Actions cache under the board and branch and restored by the next dispatch. Adopted stages are committed to `branch` with the stage range and open-edge counts; if the branch moved and a rebase fails, the commit goes to `ci-route/<board>-<run id>`. Logs, receipts and the host memory peak are uploaded as a seven-day artifact.

Pushes made with the workflow token do not trigger other workflows, so push again or reopen the PR to run the gate. `bash scripts/pcbgen/dispatch_route.sh <board> <branch> <from> [<to>] [--workers N] [--max-minutes M] [--no-wait]` dispatches the workflow and waits for the run. Pause local routing of the same board while CI routes it.

`.github/workflows/route-shards.yml` splits the hotspot-region stages of one board over parallel jobs. `route_jack_grid.py --shard I/N` plans the start board's stranded-pin regions once. Regions are spread over N shards by stranded-pin load, and every signal net is owned by exactly one shard, the one whose regions hold it most often. A shard renegotiates only its own nets in its own regions. Overlapping groups stop growing at an even share of the stranded pins. For a range of only signal/rrr stages (`signals-local`, `signals-NN`, `rrr-NN`, `signal-escapes`), the plan instead bisects net centroids by board area, balanced by open edges. A shard routes only its own open nets and passes `rip_only` to `grid_router.route`, so rip-up never touches another shard's nets. `route_shards.py delta` records the segments and vias each shard removed and added. In the merge job, `route_shards.py merge` applies all deltas to the pinned base commit, runs the native DRC/parity/refill gate once, reverts whole nets whose new copper fails or splits a plane, and promotes the result only if native open edges fall. It writes `reports/grid-routing/shards-<run id>.json`. Dispatch it with `gh workflow run route-shards.yml --ref main -f board=<board> -f branch=<branch> -f shards=<N>`. It shares route.yml's concurrency group, and shard state is not resumed between dispatches. `python3 -m unittest scripts.pcbgen.test_route_shards` covers the plan, the delta and the text merge.
