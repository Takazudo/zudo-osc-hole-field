# PCB draft sync

Run `bash scripts/kicad/run.sh python3 scripts/pcbgen/sync.py <board-id>` after the matching KiCad schematic netlist has been exported. Board definitions live in `design/boards/<board-id>.json`; the checked-in `fixture-jacks` definition demonstrates the format. The generator reads panel hardware coordinates only from `design/grid/placements.lock.json`, then translates them with `scripts/geometry/panel_frame.py:to_kicad()`.

The definition contains a panel-frame outline polygon, optional convex corner radius, 2/4/6/8 copper-layer count, preliminary layer stackup and thickness, NPTH mounting holes, copper keepout polygons, board domains, and the exact selected lockfile UIDs. Those domains and UIDs are eligibility and coordinate inputs; the exported netlist controls which footprints are populated. Unplaced netlist parts begin in a staging lane outside the panel and keep later manual placement on subsequent syncs. The optional netlist symbol field `BoardSide` selects `F.Cu` or `B.Cu` for free parts; absent it, existing free-part flips are preserved. Fixed panel hardware must stay on `F.Cu`. `F.Cu` faces the panel and `B.Cu` faces away. The shared panel origin is translated to `(100, 50)` mm and used for both drill/place and grid origin. Board sheet size is A2.

A footprint belongs to this generator only when its UUID equals the UUIDv5 derived from the board ID and reference. The same rule applies to outline segments, declared mounting holes, and rule-area keepouts. Sync can remove those items when the source removes them. It never removes an unowned footprint, track, via, zone, text or graphic; a conflicting unowned reference fails before the generator takes it over. Existing free footprints retain their current location. Fixed hardware footprints return to their lockfile position and are locked. Library footprints are loaded once per type, then cloned. KiCad's random generated UUIDs are rewritten after save; the postpass also sorts only owned footprint/keepout blocks so repeated syncs are byte-identical. Schematic paths use the netlist sheet and symbol UUIDs.

`bash scripts/pcbgen/check.sh <board-id>` runs the pinned KiCad 10.0.6 DRC with schematic parity, zone refill and all severities, then writes JSON, top/bottom PNG renders and an SVG to `boards/<board-id>/reports/`. The summary separates rule violations, unconnected items and parity issues, and exits nonzero for DRC errors or parity issues. It does **not** claim that a clean rule check qualifies the PCB or its mechanical fit.

Run `python3 -m unittest scripts.pcbgen.test_pure -v` for board-definition and UUID tests and `bash scripts/pcbgen/test_fixture.sh` for the ten-jack oracle fixture. The fixture tests exact lockfile placement, zero schematic parity issues, byte-identical repeat sync, owner track/via/zone/text/graphic preservation, component re-netting, and component removal. Its jacks are deliberately unrouted; unconnected items are expected. The synthetic circuit and board are unvalidated drafts and are never fabrication order files.

Current limitations: the stackup JSON records intent while KiCad receives thickness and copper count; detailed dielectric/material rule values await the board-stack decision. Fillets require a strictly convex polygon. The fixture cannot establish physical jack-panel fit or electrical function.

## Region placement for repeated clusters

After sync, `place.py` positions generator-owned, unlocked free footprints within the optional `regions` in a board definition. Each region names a schematic `Block` instance and a repeated `family`, plus a panel-frame `rect` `[left, top, right, bottom]` in millimetres, `side` (`F.Cu` or `B.Cu`), `edge_clearance_mm`, and `mounting_clearance_mm`. See `fixture-place-six.json` for six 17 mm translated regions. The placement UIDs and fixed hardware coordinates still come solely from the grid lockfile. Locked or unowned free footprints keep their locations; an absent or moved fixed footprint is an error.

Export the schematic netlist, run sync, then run `bash scripts/kicad/run.sh python3 scripts/pcbgen/place.py <board-id>`. `--board`, `--netlist`, and `--report` select alternate paths. The report defaults to `reports/placement.json` beside the board. Each schematic `Block` must have a matching region. A family is placed once from its courtyard boxes, and each repeated instance receives the same relative positions translated to its region. A component with an `Island` field naming a selected panel UID is anchored near that hardware. `DecouplingOf` can name an IC `Role` or reference; otherwise shared signal nets assign nearby passives to an IC cluster. Courtyards, both-side through-hole pads, mounting holes, keepouts, and outline edges constrain legal positions. There is no spill outside the named region. An impossible placement exits nonzero and writes an `OVERFLOW` report with the instance, needed area, and available area; it does not save the board.

Run `bash scripts/pcbgen/test_placer.sh` for one-instance, six-instance, island, and overflow oracle fixtures. It checks second-run byte identity, exact 17 mm translations, zero courtyard violations, and zero schematic parity issues in KiCad 10. The fixture is unrouted, so unconnected DRC items are expected. The placer uses conservative axis-aligned courtyard boxes and a 0.5 mm search grid. Its report remains `PLACED DRAFT`; final layout and mechanical/electrical qualification require later checks.
