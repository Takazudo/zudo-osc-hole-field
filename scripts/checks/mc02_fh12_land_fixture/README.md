# Incomplete FH12 land-pattern fixtures

**INCOMPLETE_NOT_FOR_LAYOUT; NO_ADOPTION.** Four isolated nominal copper-land
fixtures for FH12-8S/14S/26S/40S-0.5SH(55), with no project reference, pad nets,
body/courtyard, 3D model or binding to any of the122 virtual endpoints.

The actual reviewed Hirose EDC3-150229-11 PDF and source inputs are hash-pinned.
Sheets1/2 recommended PCB mounting pattern identify contact1 at the left of the
signal row; sheet5 supplies exact A/F/G values. The reviewer-defined row-midpoint
frame has +X toward higher contact numbers and +Y toward mounting tabs. This is
not a project footprint placement transform.

- Signal lands: numbered1..n,0.5mm pitch,0.3×1.3mm, row y=0.
- Two mounting lands: **unnumbered**,1.8×2.2mm; F=A+2,G=A+5.6,A=0.5(n−1).
  Their centers are x=±(F+G)/4,y=1.3/2+1.5+2.2/2=3.25mm.
- Copper only: F.Cu in library files. Paste and mask apertures are deliberately
  absent; the recommended stencil width is a separate source quantity.
- No AGND assignment, fabrication export, adopted courtyard or physical envelope.

```sh
python3 -B scripts/checks/mc02_fh12_land_fixture/native_check.py \
  --fixture-dir "$PWD/.circuit-cache/fh12-land-fixture/unique-run"
```

`native-results/` is reserved before importing pcbnew. For each of32 cases
(four variants×F/B×0/90/180/270 degrees), the checker uses FootprintLoad, sets an
isolated(100,100)mm board origin, applies the side/cardinal transformation, saves
a disposable board and reloads it. It compares numbered/unnumbered pad counts,
integer-nanometer positions/sizes, rectangular pad orientations modulo180,
exact copper-only layers, zero nets, no graphics/models and the explicit
incomplete description before and after roundtrip. Counter comparisons preserve
both unnumbered tabs. Orientation is tested independently of pad sizes; rectangular
180-degree equivalence is accepted, while a90-degree shape error is rejected.

The native oracle uses its own literal EDC sheet5 A/F/G table and independent
integer land construction; it never calls the generator's pads function or
trusts fixture pad records as expected geometry. A mutation regression proves
changing the generator cannot change the native expected rows.
The expected matrix is independent integer cardinal arithmetic: B canonical local
frame mirrors y, then the KiCad clockwise-positive rotation is applied. Flip is
followed by explicit SetOrientationDegrees. Existing repository examples supply
FootprintLoad/Flip/SetOrientationDegrees/SaveBoard/LoadBoard patterns. The official
[FOOTPRINT API source](https://docs.kicad.org/doxygen/footprint_8cpp_source.html)
explains flip orientation handling; the current web docs are not a substitute for
actual pinned10.0.6 binding verification. Unsupported APIs or unexpected geometry
fail the admitted native attempt; no fallback, guessed success or changed model.

Synthetic tests include literal A/F/G values independently transcribed for all
four variants, asymmetric cardinal transforms and wrong pad rotation/layer/net
scope rejection. They do not prove KiCad parser/API compatibility. Native success
would establish only this disposable land-fixture roundtrip, never full footprint
qualification, endpoint registration, mounted access, DRC/fill or adoption.
